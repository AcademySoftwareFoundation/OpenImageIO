# Format Hardening Deferral Log

Tracking document for the format-by-format security & stability audit
(`specs/002-format-security-audit/`). It records hardening issues that are
**spotted but deliberately not fixed in the current format phase**, so they are
not forgotten and can be scheduled later (spec FR-015, FR-016).

## What goes here

- **Writer-side defects** that are *not* obvious shared hazards of the reader
  (FR-014) — i.e., not a direct analog of a reader defect found in the same
  phase. Obvious shared-hazard writer bugs are fixed in the format's own phase
  and do NOT belong here.
- **Unrelated bugs** found incidentally during a format audit that live in
  shared/helper code or a different format and are not fixed immediately
  (FR-016). If fixed immediately, they go in their own separate commit/PR
  instead of being logged here.
- Any other reader-hardening opportunity intentionally postponed.

## What does NOT go here

- Defects fixed within the current format phase (they are in that PR).
- Cosmetic/stylistic issues that are not "material" per FR-012 (no crash, hang,
  memory-safety, or incorrect-decode potential).

## Severity guide (from the project constitution)

- **P0** — memory-safety violation (ASan/UBSan finding). Fix within 72 hours of
  scheduling; blocks unrelated merges if unfixed after 72 hours.
- **P1** — crash without sanitizer annotation. Fix within one week.
- **P2** — robustness/correctness issue without a direct memory-safety or crash
  vector.
